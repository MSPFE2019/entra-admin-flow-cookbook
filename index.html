Set up the app and scheduled flow

Use the exact least-privileged Graph Application permission for the recipe endpoint, with admin consent. The cloud choice above changes the displayed Graph host and OAuth authority.

1 · App registration

  1. Register the app in the same Entra cloud as the target tenant.
  2. Add only the permission(s) shown in the recipe and grant admin consent.
  3. Use a certificate if supported; otherwise protect the secret in an approved secret store and define rotation ownership.
  4. Do not put credentials in Compose, email, source files, or chat.

2 · Scheduled flow

  1. Create a Scheduled cloud flow with a Recurrence trigger.
  2. Add an HTTP GET action or approved custom connector; use the selected cloud's host and OAuth authority.
  3. Parse the JSON response, iterate over value, and follow @odata.nextLink until no page remains.
  4. Handle 429/5xx responses with retries and keep notifications scoped to approved recipients.

3 · Verify before enabling

  1. Test with a short date window or small $top value when supported.
  2. Check permission requirements on Microsoft's endpoint reference before consent.
  3. For recurring digests, store a watermark or processed IDs to prevent duplicate messages.
  4. Confirm premium connector licensing, government-cloud availability, DLP, and data retention.

Many Power Automate HTTP patterns require premium licensing. GCC High uses graph.microsoft.us and login.microsoftonline.us; verify the exact availability and API support in your cloud.
